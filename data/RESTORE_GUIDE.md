# 회차 복원 작업 지침 (데이터 레인)

> 이 문서는 `SCHEMA.md`(동결 스키마)의 **작업 절차** 편이다. 스키마 자체는 SCHEMA.md 가 authority.

## 입력 자료

회차 `{R}` 의 수집 원본은 전부 `data/raw/{R}/` 에 있다. 네트워크 재수집 불필요.

| 파일 | 내용 |
|---|---|
| `page.txt` | 본문 평문. **지문·정답의 1차 소스.** 표는 탭 구분, 이미지는 `[IMG <url>]` 자리표시 |
| `article.html` | 본문 HTML 원본. 표 구조·코드 들여쓰기 확인용 |
| `page.html` | 페이지 전체 HTML |
| `imgNN.png` / `imgNN.jpg` | 다운로드된 이미지. **표·코드·다이어그램은 여기 있다** |
| `images.json` | `imgNN` ↔ 원본 URL 매핑 (본문 등장 순서 = index 순서) |

## 1문항 표준 절차

1. **`page.txt` 에서 문항 경계를 찾는다.** 문항은 `N. ` 로 시작한다.
2. **정답은 `더보기` 바로 다음 줄들에 있다.** 티스토리 접힘 블록이 평문으로 펼쳐진 결과다.
   `더보기` 아래에는 정답 + 해설이 이어지므로, **정답만** 취하고 해설은 버린다.
3. **이미지 판독**: 문항 위치에 `[IMG …]` 가 있으면 `images.json` 으로 `imgNN` 파일명을 찾아
   **Read 도구로 그 이미지를 실제로 열어 판독**한다. 추측 금지.
   판독 결과를 `bodyHtml` 의 `<table class="tbl">` 또는 `<pre class="code">` 로 재현한다.
   그 문항의 `sourceImages` 에 `raw/{R}/imgNN.png` 를 반드시 기록한다.
4. **코드 블록 정리**: 티스토리 코드 하이라이터 때문에 `page.txt` 의 코드는
   앞쪽에 `1 2 3 4 …` 줄번호가 한 줄씩 흩어져 있고 끝에 `Colored by Color Scripter` / `cs` 가 붙는다.
   **줄번호와 그 꼬리표는 제거**하고, `article.html` 을 참고해 원래 들여쓰기를 복원한다.
5. `bodyHtml` / `bodyText` / `prompt` / `sampleAnswer` / `display` / `sourceImages` 를 채운다.
6. 회차 완성 → `npm run validate` 통과 → `data/PROGRESS.md` 갱신.
7. 판독 불가 문항은 JSON 에서 제외하고 `data/excluded.md` 에 **사유와 함께** 기록한다.
   제외해도 남은 문항의 `num` 은 **원본 문항 번호를 그대로 유지**한다 — 재번호 금지.
   validate 는 `num` 의 엄격 오름차순과 `id === "{round}#{num}"` 만 검사하며 **빈 번호를 허용**한다
   (예: Q7 제외 시 `#6` 다음이 `#8`). `excluded.md` 의 "Q7" 이 JSON 의 `#7` 부재와 1:1 대응되어야 하기 때문이다.
8. **서술형 문항("…의 개념을 서술하시오", 정답이 문장)** 은 제외하지 않는다. `keywords` validator 를 쓴다:
   ```json
   { "label": "답", "accept": [], "normalize": "default",
     "validator": { "type": "keywords", "all": ["무결성"], "any": ["제약", "규칙", "조건"], "minAny": 1 },
     "sampleAnswer": "무결성 제약조건" }
   ```
   - `all` = 그 개념을 말했다고 인정하려면 **반드시** 나와야 하는 핵심어 (보통 1~2개).
   - `any` = 그중 일부만 나와도 되는 보조 개념어. `minAny` 로 최소 개수 지정.
   - 키워드는 짧게(2~4글자 어근). `"무결성 제약조건"` 처럼 긴 구를 키워드로 넣으면 어순이 조금만 달라도 오답이 된다.
   - `display` 에 원문 모범답안 전문을 넣는다. `sampleAnswer` 는 키워드를 전부 포함하는 짧은 구.
   - 정답이 단어 하나(용어)인 문항은 서술형이 아니다 — 평소대로 `accept` 열거.
   - **키워드는 "이 개념을 이웃 개념과 구별하는 말"로 고른다.** 주제의 일반 어휘로 채우면 이웃 개념 답이 통과한다
     (감사에서 실제 발생: 스니핑 spec 의 `패킷·네트워크·트래픽` 은 스푸핑 답도 통과시켰고, 가용성 spec 의 `권한·접근·사용자` 는
     기밀성 답을 통과시켰으며, 원자성 spec 의 `반영·완료` 는 지속성 답을 통과시켰다).
     작성 후 **반드시 이웃 개념 문장 2개로 오답 판정을 확인**한다 (같은 page.txt 안의 옆 해설이 가장 좋은 시험 문장이다).
   - `default` 정규화는 공백을 전부 지우므로 키워드는 단어 경계 없이 부분 일치한다. `사용` 은 `사용자` 에 걸린다 →
     `사용할 수 있` 처럼 구별되는 형태를 쓴다. 한 글자 키워드 금지(`형` 은 형상·유형·모형에 걸린다).

## 마크업 규약 (기존 자산 계승 — 클래스명 변경 금지)

| 요소 | bodyHtml | bodyText |
|---|---|---|
| 설명 지문 | `<div class="desc-box">…</div>` | 평문 단락 |
| 표 | `<table class="tbl"><tr><th>…</th></tr><tr><td>…</td></tr></table>` | 마크다운 표 |
| 코드 | `<pre class="code">…</pre>` (`<` `>` `&` 는 엔티티) | ` ```lang ` 펜스 |
| 보기 | `<div class="boki"><b>[보기]</b> …</div>` | `[보기]` + 줄바꿈 목록 |
| 부가 안내 | `<div class="hint">※ …</div>` | `※ …` |

- `bodyText` 는 **AI 질문 프롬프트에 그대로 들어간다.** HTML 태그·엔티티가 남으면 안 된다.
  `bodyText` 첫 줄은 `prompt` 의 평문판으로 시작한다.
- `bodyHtml` 에 **블로그 이미지 URL을 절대 넣지 않는다** (서명 URL 만료 → validate 가 차단).
  이미지 내용은 표/코드/텍스트로 **재현**한다.

## accept 작성 규약

- 한글 용어는 **표기 변형을 넉넉히** 나열한다: `동치분할`, `동등분할`, 영문 `equivalence partitioning`,
  괄호 병기형 `동치분할(equivalence partitioning)`.
  `default` normalize 가 공백을 전부 지우므로 accept 안의 공백은 무해하다.
- 기호 답(`ㄱ`,`ㅁ`)이 정답이면 기호와 용어를 **모두** 인정한다.
- **코드 출력 문항**은 `normalize: "keepSpace"` 를 쓰고, 대소문자 무시를 유지하려면
  accept 에 대문자형·소문자형을 **둘 다** 넣는다. (예: `["CNNLRPYT","cnnlrpyt"]`)
  이유: `default` 의 전공백 제거는 `"C N N L R P Y T"` 같은 오답을 잘못 인정한다.
- 순수 숫자 답은 `default` 로 둔다.
- 다중 단어 SQL 답(`ORDER BY`, `GROUP BY` 등)은 `normalize: "sql"`.
- `"N가지를 쓰시오"` 유형 → `answerMode: "unordered"`, 필드 N개, **전 필드 동일 normalize**.
- 계산형(임의의 유효 IP 등)만 `validator` 를 쓴다. validator 필드는 `accept: []`.
  **새 validator 타입은 임의로 만들지 말 것** — SCHEMA.md 의 3단계 절차 대상이며 team-lead 승인 필요.
  열거로 표현 가능하면 열거를 우선한다.

## sampleAnswer / display

- `sampleAnswer` — **반드시 채점을 통과하는** 예시 정답. validate 가 전건 자가 채점한다.
- `display` — 오답 시 사용자에게 보여줄 사람용 정답 전체 표기. 다필드는 `(1) … / (2) …` 형태.
  HTML 태그를 넣지 않는다(평문 + `/` 구분).

## 완료 조건

회차 하나는 아래 3개가 모두 참일 때 완료다. `data/PROGRESS.md` 3열 체크리스트에 기록한다.

1. **복원완료** — 전 문항 JSON 작성
2. **validate통과** — `npm run validate` 에서 해당 회차 PASS
3. **감사통과** — 독립 재판독 감사 통과 (감사 담당자가 기록)

## 감사 규약 (별도 담당자)

- 회차 문항의 **20%(최소 4문항) 무작위 표본**을 `sourceImages`·`raw` 원본만 보고 독립 재판독해 대조.
- **추가로**, `validator` 문항 / 다필드 문항 / 코드 출력 문항은 **100% 감사** (오독 시 채점 영향 최대).
- 불일치 등급:
  - **A급** — 채점 영향 또는 지문 내용 변경: `bodyHtml`/`bodyText` 의 수치·식별자·코드 리터럴·표 셀 값,
    `accept`·`validator`·`sampleAnswer`·필드 수·정답 자체.
    → **A급 1건 이상이면 해당 회차 전 문항 재감사.**
  - **B급** — 순수 표시 서식: 줄바꿈·정렬·클래스·공백. → 수정 후 기록만.
- 감사는 표본 검사이므로 완전 보증이 아니다. 운영 중 "정답 이의 제기" 버튼이 상시 신고 경로다.

### 감사 판정 세칙 (실감사에서 확정된 기준)

- **이미지→산문 전사의 사실 불일치는 정답 불변이어도 A급**이다 ("지문 내용 변경" 조항). 예: 다이어그램에 1개뿐인 라벨을 두 화살표에
  적은 것, 밑줄(키 속성)을 빠뜨린 것. 전 문항 재감사 비용은 감수한다.
- **A급 처리 절차**: 수정 → validate + `npm test` 재통과 → 워크시트에 before/after → 전 문항 재감사 → 그 후 감사통과 체크.
  2026-2 만 예외: 골든 기준선이므로 수정 전에 lead 에 먼저 보고.
- **원문 오타 정책**: 해설·정답의 오타는 교정한다(`laas`→`IaaS`). 보기 항목·코드·식별자의 오타는 **보존**한다 — 응시자가 골라 적는
  채점 대상이거나 시험 화면 그대로가 맞다(`swich`, `.Length`, `extend`). 단 문항이 읽히지 않게 만드는 오타(`SELECT DERP` 인데 발문이
  DEPT 를 전제)는 교정하고 워크시트에 근거를 남긴다. 한글 지문 산문의 단순 오타(`오프젝트`, `권한하고`)는 교정해도 되나 정답·식별자와
  무관해야 하며, 회차 안에서 한 방향으로 일관되게 처리한다.
- **"N가지를 쓰시오"라도 예시가 번호로 묶여 각 답을 슬롯에 고정하면 `ordered`** 다 (2021-1 #9). unordered 는 슬롯 구속이 없을 때만.
- **복원자가 추가한 hint·안내 문구는 원문에 없는 지문이므로 A급 검사 대상**이다 (2025-2 #11 — hint 의 "예: …" 가 곧 정답이었다).
  형식 안내는 허용하되 정답·정답 일부·정답 개수를 유추시키는 내용은 금지.
- **닫힌 보기에서 고르는 다필드 문항의 `accept` 에 같은 보기의 경쟁 항목이 섞이면 A급**이다 (2024-3 #13 — 2번 필드가 정답 외에
  ㄷ/결정 까지 인정해 오답 보기를 골라도 정답 처리됐다). 각 필드 accept 는 그 슬롯의 정답 항목 표기 변형만 담는다.
  단, 같은 회차 안에서 서로 다른 문항의 정답이 겹치는 것은 무관하며, 개방형(보기 없음) 문항의 동의어 열거는 이 규칙 대상이 아니다.
- **닫힌 보기 집합 안에서 고르는 IP 문항은 validator 가 아니라 `accept` 열거**다 (2024-1 #5) — validator 를 쓰면 보기에 없는 임의
  호스트까지 정답이 되어 문항 취지가 깨진다. 임의 호스트를 묻는 2026-2 #10 만 validator.
